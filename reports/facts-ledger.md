## 维护方式

1. 每次引用高频硬数据前查本表；表中没有的，写作时先核验再补录。
2. 数值更新流程：**先更新本表 → `grep` 全站旧值 → 逐处同步 → 跑质量门 → 原子推送**。
3. 定期跑 `python3 scripts/data_freshness_audit.py` 扫描陈旧度与跨文数值冲突。
4. 质量门 Gate 13 只保证「硬数字挂了来源」，**不保证数字没过期**——过期由本表 + 审计脚本把关。
5. **写作时新引入任何《报告名》，先做三问**（2026-08-03 新增，因一次性查出 3 个虚构报告 + 3 处信源伪装）：
   - **它存在吗？** 搜报告全名 + 发布方。搜不到发布方 = 不能写。
   - **谁发布的？** 只标「2026年X月发布」而说不出机构名的，一律视为高危。
   - **它配得上这个证据等级吗？** 个人博客、GitHub Pages、知乎/腾讯云开发者社区等 UGC，
     可以引用观点，但**必须如实标明是个人/社区文章**，禁止称其为「报告」「研究」「调研」。
6. **自动化测不出的盲区**：`quality_gate.py` 与 `fact_risk_census.py` 都只检查「形态」
   （有没有时间锚、有没有出处锚），**无法判断出处真伪与权威等级**。这一层只能靠写作期核验 + 本表。
