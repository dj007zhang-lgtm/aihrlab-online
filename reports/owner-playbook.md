## 一、品牌愿景（Vision & Mission）

> 来源：`roadmap-2026-08.md` §0。KPI 是仪表盘，不是目标本身。

- **使命**：成为 AI+HR 领域最可信的中文知识中枢——既被从业者日常依赖（高阅读 / 点赞 / 收藏），也被生成式引擎稳定引用（GEO）。
- **愿景态架构特征（内容网站理想态）**：
  1. 内容即结构化资产（内容集合，而非 130+ 散落手写 HTML）——Track A。
  2. 内容优先静态生成（零 JS 默认、快、稳）。
  3. 卓越阅读体验（流体排版 + measure 控制 + sticky TOC）——Track B。
  4. 可发现性内建进结构（非事后补丁）——Track D。
  5. 自带用户沉淀层（邮件 + 社区，不只有公众号）——Track C。
  6. 资源库即知识中枢（统一存取层）。
- **门面纪律（红线）**：slogan＝门面（front face），≠ 脊梁（spine）。脊梁＝135+ 硬信源深文。slogan 仅做首页 / 关于页定位，绝不可取代内容 spine（依据 `ADR-20260817-001`、R-07）。
- **落版主张（2026-08-17 拍板）**：
  - 首页 hero（风格③极简高管风）：「为组织决策者，过滤 AI 时代的管理噪音。立足硬核信源，穿透大厂实战。只做重度研究，只交付落地解法。」
  - 关于页（风格①冷峻智库风）：「驱动组织进化的 AI 智库。学术级信源与一线实战，过滤行业喧嚣，重度研判。」
  - 避风格②引擎驱动风（「领航者」「决策引擎」＝过度宣称 / 偏营销，撞不营销红线）。

## 二、核心价值观（Core Values）

> 两套底线叠加：**内容宪法**（写什么不写什么）+ **设计原则**（怎么做不怎么做）。两者都是下限兜底，标准只升不降。

### 2.1 内容宪法（事实诚信 / 零虚构 / 不营销）
- **基于事实、零虚构**：精确大额数字无出处不写；投资 / 股权 / 合作 / 任职关系须 WebSearch 核验（R-02）。
- **不营销**：禁点赞/在看/转发三连式呼吁、禁末日恐慌叙事、禁口号 spine 替代脊梁（R-05/06/07）。
- **不下权力审判**：停在机制解剖（权力 / 筹码 / 定价权 / 护城河），不给读者训诫、不居高临下（R-08/09）。
- **语域纪律**：不用物理借词框架（路由器/熵增）、不文学诗意隐喻、破折号规范、H2 无句末标点（R-10/11/12）。
- **一篇一论**：禁一稿多论平铺综述巡礼，证据编织进正文作注脚（R-13）。
- 完整条款见 `content-redlines.md` R-01..R-14（单一真相源，仅增不减会打架，新增必合并、过时即 retire）。

### 2.2 设计原则（6 条，来源 `design-principles-v1.md`）
1. **视觉语言服从品牌**：1–2 个品牌色即可；国内常见「什么都要」反而失焦。
2. **动效必须有目的**：服务于信息传递 / 产品演示；纯炫技掉价。
3. **网格 + 留白是基本功**：12 列网格 + 大量留白（国内最忽略项，我们曾中招，正修）。
4. **内容敢于裁剪**：不堆「四件套」，只放核心——裁剪**只作用于首页 / 列表 / 首屏 / 导航**，文章正文继续深（张力化解纪律）。
5. **移动端是默认**：不是桌面版的缩小，而是重设计。
6. **性能也是设计**：即便重 3D，也要做移动降级。

### 2.3 洞见（不可绕过的取向）
- **75% 可信度来自设计**（Stanford PAPL / Fogg 2002），但须与「内容可信」并用，单靠设计救不了空内容。
- **趋势会变、「为用户设计」不变**：勿为追 trend 而 neo / 3D。
- **设计是产品 / 工程 / 运营共同的事**：对应 A / B / C / D / Q 子代理模型。

### Track 映射（架构前置，来源 roadmap §2）
- **Track A 架构级重构**（前置 · 混合 C）：内容即资产、新文 MDX 化、排版 token 化、旧 130 篇分批重制。

- **M2**（2–4 周）：B 全站排版统一冲 D 跳出率 + A4 旧文首批重制（高价值 30 篇）。

## 四、整体设计系统规范（Design System）

> 来源：`MEMORY.md` 设计系统段 + `design-principles-v1.md` + `R1-dark-mode-charter.md`。

### 4.1 色彩 Token（森林绿系 + 深色 R1）
**浅色（`:root`）**
| 角色 | 值 |
|---|---|
| 深林绿（品牌主色） | `#3F6212` |
| 陶土棕（强调/点缀） | `#A86A2E` |
| 暖沙（背景基底） | `#F1EFE9` |

**深色（`:root[data-theme="dark"]`，R1 护眼模式）**
| 角色 | 值 |
|---|---|
| bg | `#0B0C0E` |
| text | `#ECEAE4` |
| text-link | `#9CC06A` |
| accent | `#6F9A3C` |
| surface | `#16191D` |

### 4.2 Ghost Token 护栏（致命雷区，已扫无残留）
- `--bg-muted` / `--color-accent` **从未定义**，曾裸引用致透明背景。真实 token＝`--bg-subtle` / `--accent`。
- 扫描须同时覆盖裸 `var(--bg-muted)` 与带回退 `var(--bg-muted,#x)` 两类。Gate 扫描纳入。

### 4.3 排版与节律
- 正文 **measure 68–72ch**（`max-width` 收至 72ch + `text-wrap:pretty`）。
- h1–h4 用 `clamp()` 设计 token 复用，禁裸 `font-size:2.xrem` 硬编码（B1）。
- 行高 / 段距节律统一（流体排版）。

### 4.4 网格 + 留白
- 12 列网格 + 大量留白；四类卡片（articles / resources / glossary / tools）间距对齐设计容差（B4）。
- 内容裁剪只作用于首屏 / 列表 / 导航（给 1 个清晰 next-hop），文章正文继续深。

### 4.5 动效与性能
- 动效当产品功能（hover / scroll / loading），非炫技（Track B M2）。
- 性能也是设计：移动降级；未实测 Lighthouse 前不宣称性能达标（Track B M4）。

### 4.6 可访问性
- 深色模式对比度复检（R1 后新增组件无透明 / 爆亮，B5）。
- 移动端是默认（响应式断点健康度待审计，B M3）。

## 五、迭代升级的具体要求（Iterative Upgrade Requirements）

> 来源：`MEMORY.md` 发布铁律 + SDLC 体系 + `content-redlines.md` 维护纪律。

### 5.1 SDLC 6 阶段 + 可追溯 ID
- 阶段：REQ（需求）→ DES（设计）→ CHG（变更）→ TST（测试）→ DEP（部署）→ INC（事件）/ LSN（复盘）。
- 可追溯 ID 格式：`{TYPE}-{YYYYMMDD}-{NNN}`，例 `CHG-20260817-001`。
- 配套：process 目录骨架 + registries + 乐享镜像（单一主线，禁双版本）。

### 5.2 双闸质量门（零绕过，固化进 CI）
- **Gate 0–22**（`quality_gate.py --all`）：二维码唯一 / 内链 / 结构 / H1 / 视觉 / 品味 / SEO / Diff / 尾页一致 / 标题一致 / 延伸阅读截断 / URL 一致 / 信源时效 / 硬数据出处 / 读者视角（≥80 放行）/ 共享资源完整性 / 文章索引完整性 / 内链图谱健康 / 内联脚本运行时语法 / JSON-LD 校验 / Sitemap 卫生。
- **stability_guard 11 项**（`stability_guard.py --all`）：预发布稳定性自检。
- **读者视角门**（`reader_perspective_gate.py ≥80`）：发布前代入读者全环节诊断（封面 / 号内标题 / 正文图文 / 图注承接），严禁「用户发截图我才改」被动模式。
- 三层事实防线：Gate13 硬数据出处 + `reports/facts-ledger.md` + `reports/source_registry.json` allow/deny。

### 5.3 发布铁律（MANDATORY，7 条）
1. 新文从 `templates/article-v2.html` 复制（唯一 canonical 模板）。
2. 唯一入口＝`scripts/publish.py`；双闸 `quality_gate.py --all` → `stability_guard.py --all`。
3. 严禁源码硬编码密钥（`git_atomic.py` 的 TOKEN 从 `AIHR_GITHUB_TOKEN` 或 gitignored `scripts/.github_token` 读取）。
4. 发布走 `git_atomic.atomic_commit`（Git Data API 原子提交：blob→tree(base_tree)→commit→PATCH refs/heads/main，单次多文件一 commit，无 `git add -A`、无逐文件 PUT）。
5. 沙箱出网代理放行 `api.github.com`、拦截 `github.com` 主域名 → 原生 `git fetch` 超时；用 API `GET /git/refs/heads/main` 取真 HEAD sha 核对发布结果。
6. `_RETRYABLE_HTTP` 已含 400/429，瞬断可重试。
7. **本地/远程漂移雷区**：本地 `origin/main` 因 API 发布而不更新，已上线文件在本地表现为 untracked；判定断链 / 发布 / 索引状态一律以 API 取真实 main 为准，勿信本地 `git status`。

### 5.4 维护即 retire 纪律
- 红线 / 标准 / 设计条款「只增不减会打架」：新增必合并冲突项，过时即替换并记 retire 日志，不留僵尸条款。
- 标准阈值可升（SDLC 原则「标准只升不降」），禁为「显得活」而跨红线（R-14）。

## 六、主理人自主能动性机制（Autonomous Initiative）

> 来源：`MEMORY.md` 主理人授权 + 主动监控红线。用户授权 AI 当主理人、自主出活，只关键节点同步；不每步回头求证、把选择题甩回用户。

### 6.1 子代理模型（独立收口、双闸零回归、验收归主理人）
- **A-Architect**（架构）/ **B-Typographer**（排版体验）/ **C-Growth**（增长沉淀）/ **D-SEO**（GEO 索引）/ **Q-Guard**（横切质量守卫）。
- 职能与交付见 `aihr-reconstruction-team.md`；项目 KB + 任务看板在乐享「AIHR 架构重构作战室 2026-08」。

### 6.2 授权边界（最高优先级）
- 内容方向由用户给，执行与补全由 AI 自主完成（用户原话「核心是一起输出硬核内容」）。
- 主理人主观能动底线：配色 / 构图 / 字号等取舍由 AI 自行判断，仅关键分歧点同步；不把已被否决的选项甩回用户求证。
- 用户定调未必都对，AI 对数据负责：taste 点若与事实或 spine 冲突，AI 要指出并守住，而非盲改数据迎合。

### 6.3 主动监控红线（不可绕过）
- 搜索生命体征（GSC 有效页 / 曝光 / 点击）是站点生命线，归零＝站点死亡。主理人**必须主动监控**，不能等用户截图才发现。
- 机制：`tools/vitals_monitor.py`（每周一 automation 触发）+ 用户本地 `tools/metrics_pull.py --gsc` 产出快照提交仓库。
- 沙箱无 Google 出口（oauth2.googleapis.com 超时）是已知限制，**不构成不监控借口**：
  - monitor 走 offline 模式读已提交快照；无新鲜快照 → 显式写 BLOCKED/STALE 报告并要求用户在本地补拉、**下轮必跟进**。
- 归零（近 7 日曝光/点击＝0 且前期>0）→ **P0 致命**；骤降 >60% → **P1**。二者**先于一切其他工作**处理，并向用户同步根因与恢复 ETA（1–4 周）。
- 每次发布经 `scripts/publish.py` 留「发布印记」`reports/publish-manifest.json`（date/commit/sitemap 覆盖率前后），供覆盖率骤减溯源。
