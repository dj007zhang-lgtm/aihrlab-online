# AIHR 设计系统 V5.0 适用性评估与落地方案

> 评估对象：`/Users/andyzhang/WorkBuddy/2026-07-21-22-36-56/aihr-design-system-v5.html`
> 对比基线：网站现有 Design System v1.0（`site-migrated/assets/css/style.css` + `.workbuddy/memory/MEMORY.md` 设计系统段）
> 评估日期：2026-08-05
> 结论先行：**条件性适用（部分适用），不可整体替换；可选择性移植「颜色无关」的增量优化，品牌色再决策须由主理人拍板。**

## 一、v5 设计系统的真实定位（先看清它是什么）

v5 标题即写「**三表面治理 · 微信诚实版**」，其自我定义把体系拆成三个表面：

| 表面 | 载体 | 在 v5 中的角色 |
|---|---|---|
| ① 网站轨 | 本网站页面 | 自我声明「= V4.0 完整参考」，即**仅继承、无 net-new** |
| ② 卡片轨 | 公众号封面 / 金句卡（导出 PNG，锁色） | v5 主战场之一 |
| ③ 正文轨 | 公众号长文富文本（微信反色） | v5 主战场之一 |

**关键判断：v5 本质上是一套「公众号（私域）内容生产设计系统」**，其约 60% 的篇幅与创新（卡片轨、正文轨、微信硬纪律）都服务于公众号封面/金句卡/长文排版。它声称的「网站轨」只是复用前代 v4，**对网站本身几乎没有新增主张**。

## 三、可行性结论

**总判定：条件性适用（PARTIAL）。v5 不可作为网站设计系统的整体替换；其可被网站吸收的部分仅限于「颜色无关」的增量优化。**

三条根因：

1. **品牌身份冲突（硬冲突）**：v5 的全部视觉识别建立在「橄榄绿 + 黑曜石 + 摆脱大厂蓝」之上，与网站已立项的 **引擎蓝 `#3B5BDB`** 品牌直接对立。采用 v5 配色 = 全站 rebrand，这违反「品味/定调由用户给、AI 对数据事实负责而非对品牌色负责」的分工纪律。**此步必须由主理人决策，AI 不单边执行。**

2. **v5 主体是公众号系统，不是网站系统**：v5 的核心创新（卡片轨、正文轨、微信渲染诚实纪律）全部服务于公众号私域生产；其自承「网站轨 = V4.0 完整参考」。对作为 SEO/GEO 公域入口的网站而言，v5 的 net-new 贡献稀薄。

3. **网站有完整 CSS 能力，v5 的微信约束不适用**：我们是基于 GitHub Pages 的纯静态站，拥有 `<style>`/`@media`/嵌字体全能力。v5 为公众号写的「禁止 media query、禁止嵌字」等硬纪律，对网站不仅无用，反而限制表达。

**能否提升品味与审美？**
- 客观说，v5 的「橄榄 + 黑曜石 + 思源宋体 900」审美确实更高级、更「硬核」、更契合 OD 尸检报告式冷峻定位，**前提是你开放品牌方向**。
- 但对网站而言，能真正迁移且**不换色**的品味杠杆是增量性的：缓动一致、圆角收敛、字阶系统化、可选 Latin 几何字体。这些能小幅提品味，但撑不起「整体审美跃迁」——后者只有走品牌色再决策（见第六节）才成立。

**结论：v5 是一份优秀的公众号设计系统；作为网站设计系统，它「部分可用、整体不可替换」。建议路径 = 选择性移植颜色无关优化 + 把品牌色决策交回主理人。**

## 四、可安全落地的部分（保留引擎蓝，颜色无关）

| # | 优化项 | 现状缺口 | 落地动作 | 风险 |
|---|---|---|---|---|
| 1 | **缓动统一为苹果缓动** | `--ease` 仍是旧曲线，仅搜索弹窗用了苹果缓动 → 全站不一致 | 把 `--ease` 改为 `cubic-bezier(.16,1,.3,1)`，全站统一 | 无（纯收益） |
| 2 | **字阶单变量化** | 固定 rem，改一档要手动改四处 | 引入 `--type-ratio:1.333` 链式推导 h1–h4/body | 低；需回归标题视觉 |
| 3 | **圆角收敛** | 按钮 50px/24px/卡片 16px 混用 | 主按钮统一小圆角（4–8px），保留搜索药丸作为特例 | 低；动搜索钮属既有语言 |
| 4 | **可选 Latin 字体** | 系统栈，Latin 排版一般 | 仅给拉丁字形加 `Plus Jakarta Sans`（CJK 仍走系统/思源）；**须自托管 + preload，禁 @import 阻塞** | ⚠️ web font 加载伤 LCP/SEO，须预加载或放弃 |
| 5 | **深苔绿作强调色可用性核查** | — | 若未来引入橄榄系，注意 `#5C8A2C` 在 `#F1EFE9` 上对比度仅 **≈3.56:1**，仅够 AA 大文本/UI，禁用于正文小字 | 无障碍硬约束 |

> 第 4 项与品牌色无关但涉及性能取舍；建议默认**不做 web font 加载**（维持系统栈），除非单独评估 LCP 影响。

## 五、落地实施方案与步骤（若采用「选择性移植」）

> 以下仅动 `assets/css/style.css` 的 token 与少数类，**不碰任何文章 HTML、不改品牌色**。

**Step 1 — 缓动统一**
- 文件：`assets/css/style.css`
- 改：`--ease:cubic-bezier(0.25,0.46,0.45,0.94);` → `--ease:cubic-bezier(.16,1,.3,1);`
- 验证：`grep -c "cubic-bezier(.16,1,.3,1)"` 覆盖全部过渡；`--ease` 引用处一致。

**Step 2 — 字阶单变量化**
- 在 `:root` 增加 `--type-ratio:1.333; --fs-cap:0.75rem; --fs-body:calc(...)` 链；将 h1–h4 的 `font-size` 改为 `var(--fs-*)`。
- 验证：标题视觉与现稿相近（误差 < 2px），`quality_gate.py --all` 通过。

**Step 3 — 圆角收敛**
- 主 CTA/按钮 `--radius-*` 对齐 4–8px；搜索药丸保留 `--radius-full` 作为唯一例外并加注释。
- 验证：按钮类目测无破版。

**Step 4 —（可选）Latin 字体**
- 若做：自托管 `Plus Jakarta Sans` woff2 + `<link rel="preload">`，仅作用于拉丁字形；跳过则保持系统栈。
- 验证：Lighthouse LCP 不退化（对比基线）。

**Step 5 — 回归**
- `python3 scripts/quality_gate.py --all` 须 14/14 通过。
- 抽样 3 篇长文 + 首页/资源库目测确认无破版。
- 经 `scripts/publish.py`（强制入口）原子推送。

## 六、品牌色再决策（须主理人拍板，不自动执行）

v5 的橄榄身份是否用于网站，是品味/定调决策，不在 AI 执行权限内。三个选项：

- **A. 维持引擎蓝（推荐）**：网站只做第四节的颜色无关优化；v5 的橄榄体系留给公众号侧独立使用（公众号本就是 v5 的主战场）。品牌一致、风险最低。
- **B. 全站采用 v5 橄榄身份**：网站 + 公众号统一换肤为橄榄/黑曜石。审美跃迁最彻底，但 = 推翻 DS v1.0 引擎蓝立项，须主理人明确授权。
- **C. 混合**：网站维持引擎蓝，公众号用 v5 橄榄。两渠道各取所长，但需维护两套 token。

**我的建议：A。** 理由：① v5 自承网站轨仅继承 v4，其创新本就不在网站；② 引擎蓝已是主理人立项品牌，单边 rebrand 越权；③ 公众号侧才是 v5 价值最大化的地方，应让 v5 在它真正适用的战场发力。

## 七、风险与规避

| 风险 | 规避 |
|---|---|
| 单边 rebrand 越权 | 品牌色变更一律走主理人决策（第六节），AI 不执行 B 选项直至授权 |
| web font 伤 LCP/SEO | 默认不加载；若做须自托管+preload 并跑 Lighthouse 回归 |
| 橄榄系对比度不足 | 即便未来引入，`#5C8A2C` 仅用于大文本/UI，禁用于正文小字 |
| 圆角收敛误伤搜索药丸 | 药丸作为唯一例外加注释保留 |
| 字阶改动连锁破版 | 改后跑质量门 + 目测抽样，经 `publish.py` 强制门禁推送 |
