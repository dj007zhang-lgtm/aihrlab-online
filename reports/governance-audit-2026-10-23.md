## 0. 先给结论

**你的判断是对的，而且比你说的更严重。**

我查了三个自动化的历史产出，问题不是"效果不好"，是**结构上不可能有效果**：

| 自动化 | 运行次数 | 实际产出 | 判别力 |
|---|---|---|---|
| 漏跑看门狗 | 27 | 同一实质风险（内容自动化停摆）连续 **8 次**报告"未解除"，零处置；依赖脚本缺失累计 **27 次**未固化；调度漂移 **8 次**未修 | 有告警，无后果 |
| 内容合规审核巡检 | 10 | **10/10 通过**，合规分 99.8→99.4，WARN 21→57 无处置；自报"报告明细缺口 16 项"后写"建议后续排查"即结束 | **为零** |
| 数据周复盘 | — | 已暂停 | — |

一个从不失败的检查没有信息量。**合规巡检 100% 通过率不是成绩，是它已经失效的证据。**

更刺眼的一条：看门狗报告过 `og:title` 缺失、脚本缺失、调度漂移——全部只是"记录"。**它是日记，不是看门狗。**

## 1. 两套体系必须先分开（本条为主理人本轮纠正）

**AIHRlab（网站）** 与 **AIHR数智引擎（公众号）** 是两套体系、两套规则。此前我一直在混用，**且混用本身已造成真实缺陷**：

**实证 E-010**：`reports/content-redlines.md` 自己写明——
> 消费方：aihr-hardcore-writing skill Stage 5 L5 禁忌门直接读本文件逐条比对

即该文件属于**公众号写作流水线**。但网站侧的 `scripts/content_compliance_auditor.py` 直接复用其中的调性类红线（R-05 营销腔 / R-06 焦虑 / R-07 slogan / R-10 物理借词 / R-11 诗意隐喻 / R-15）作为网站合规判据。

**后果**：合规巡检 57 条 WARN 里的大半是**公众号文风标准套在网站页面上的跨体系误用**，对网站不构成缺陷；而网站真正的容器完整性缺陷（元数据）零覆盖。**判别力全投在了错的体系上。**

### 分离后的规则归属

| 层 | 归属 | 内容 |
|---|---|---|
| **共同底线**（内容本身） | 两体系共用 | 零虚构、信源可核验、数据溯源 A/B/C 三级、不营销（事实诚信类） |
| **AIHRlab 网站专属** | 网站 | HTML/SEO 元数据完整性、IA 与导航一致性、URL 一致性、sitemap、四真源、JSON-LD 结构化数据、渲染版式、门禁 22 关、`ci/regression_rules.json` |
| **AIHR数智引擎 公众号专属** | 公众号 | 文风调性（R-05~R-11、R-15）、标题 D1-D7 七维、0 破折号 / 0 半角标点 / 0 危机词、封面 1080×460、正文 ≥28px、三重质量门（selfcheck / reader_gate / taste_diff）、周二 9:30 发布节奏 |

**执行动作**：网站侧巡检剥离调性类红线（归公众号体系），网站侧改由容器完整性判据接管。新增 `ci/escape-ledger.json` 每条强制标注 `system`。

## 2. 根因：四层结构性缺陷（不是疏忽，是设计错误）

### 2.1 稽查对象错位 —— 查"过程是否发生"，不查"产出是否有价值"
看门狗查的是"有没有推送"（活动），不是"推的东西有没有用"（结果）。所以它能在内容自动化实际停摆 16 天的情况下，因为夜间有人工提交而判 OK。

### 2.2 判据只覆盖容易机械化的部分
所有断言都是字面量/结构级（截断、引号、后缀、死链）。语义级损坏（两条标题拼接、跨页注入）因为"不好写断言"就没人写。
→ **难做的就不做，等于给失效模式划了保护区。**

### 2.3 无后果闭环
FAIL / ALERT 之后没有责任人、没有处置动作、没有复核。看门狗 ALERT 8 次 = 处置 0 次。而且**执行者、核验者、修复者是同一个我** —— 自己出题、自己答、自己阅卷，没有独立性。

### 2.4 无覆盖矩阵、无逃逸回溯
从没定义过"哪类失效归谁管"，也从不在事故后追问"为什么自动化没抓到"。所以空白区永远空白——直到今天。

## 4. 本次已落地的改造（不是建议，是已完成）

### 4.1 实证门禁盲区
把今天修掉的 `og:title` 历史损坏值**原样喂回门禁 9**（`gate_title_consistency`）→ **0 FAIL / 0 WARN 完全放行**。
门禁 9 的硬 FAIL 判据只有"截断 / 引号污染"，`h1 ≠ og:title` 被降级为不阻断 WARN（30 条）。**盲区是复现出来的，不是推测的。**

### 4.2 扩展规则引擎（此前只支持字面量匹配 → 结构性零覆盖的根因）
`ci/gates/regression_rules.py` 新增两种计算型 `match`：
- `meta_field_equals`：两字段必须相等（`h1 == og:title`）
- `meta_cross_page`：meta 字段不得混入他页标题（拼接 / 注入污染）

### 4.3 登记 2 条断言 + 接线 2 个消费者
- `R-META-CROSS-PAGE-CONTAMINATION`（BLOCK）
- `R-OG-TITLE-EQUALS-H1`（BLOCK，存量走显式登记册）

**接线**：此前 `gate_lesson_assertions.py` 与 `lint_diff.py` 两个消费者都没传 `corpus`，计算型规则会**静默跳过**——规则登记了却不生效，正是装饰性门禁。已全部接上。

### 4.4 端到端破坏性实测
向 `ai-layoff-7-to-40.html` 注入历史损坏值 → `lint_diff.py` 输出 🔴 阻断、**退出码 1**；恢复后退出码 0。
**同类问题下次构建即失败。**

### 4.5 不容忍静默偏差
`h1 ≠ og:title` 的 38 页进入 `ci/meta-variant-allowlist.json` **显式登记**（降级 WARN），任何**未登记的新偏差一律 BLOCK**，登记册只减不增。

### 4.6 顺带修掉的真缺陷（全站重扫 BLOCK 已归零）
- `ai-layoff-regret.html` 的 description / og:description / twitter:description 内嵌跨页引用「详见AI裁员2026年中盘点…」——meta 描述不该承载交叉引用，已删除（3 处，脚本按计数断言中止过两次，未产生半改）
- 全站重扫：**BLOCK = 0，WARN = 38（全部已登记）**

### 4.7 建立逃逸账本 `ci/escape-ledger.json`
11 条真实逃逸，每条强制回答"为什么没被自动化抓到"。规则：答不出来就必须二选一——**(a)** 加一条会失败的断言，或 **(b)** 明确登记为人工判断类并写明谁、多久查一次。**不允许第三种：既不自动化、也不指定人。**

## 5. PDCA 自闭环（重构后）

| 环节 | 此前 | 重构后 |
|---|---|---|
| **P** 计划 | 阶段目标，验收靠感觉 | 目标必须配**可证伪的验收判据**（一条命令 / 一条断言，有退出码） |
| **D** 执行 | 我执行 | 我执行（不变） |
| **C** 检查 | **我自己跑门禁、自己判通过** | **执行与核验分离**：断言由不持有改动上下文的检查执行；每次事故登记逃逸账本 |
| **A** 处置 | 修现象，写散文教训 | **逃逸 → 断言**（`regression_rules.json`）+ 更新覆盖矩阵 F1–F6 + 更新体系归属标签 |

**关键改动在 C 和 A**：此前 C 是自评（无独立性），A 是散文（无约束力）。现在 C 有独立判据，A 有强制出口。
