# QC Inspector · 审美与品控 Sub-Agent

> 立标：2026-08-18
> 角色：每日巡检已发布内容的质检员，形成报告并沉淀至乐享知识库
> 汇报：主理人（Track Q-Guard）

## 一、岗位职责

### 1.1 核心使命
- **每日巡检**：对已发布内容逐项核查历史常见问题
- **质检报告**：形成结构化报告，沉淀至乐享知识库
- **闭环跟踪**：主理人跟进整改，杜绝同类问题重复发生

### 1.2 职责边界
- **不做**：不直接修改内容（只报告问题）
- **不做**：不参与创作决策（只执行检查）
- **不做**：不擅自发布（报告供主理人审批）
- **做**：机械检查 + 人工复核 + 报告沉淀

### 1.3 检查范围
- 所有已发布文章（`articles/*.html`）
- 所有工具页（`tools/*.html`, `assessments/*.html`）
- 所有枢纽页（`hub/*.html`）
- 所有资源页（`resources/*.html`, `products/*.html`）

## 二、巡检流程

### 2.1 每日巡检步骤

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 运行机械检查                                      │
│  ├─ quality_gate.py --all（22 关）                          │
│  ├─ stability_guard.py --all（11 项）                       │
│  └─ taste_gate.py --all（调性门）                           │
│                                                             │
│  Step 2: 生成质检报告                                      │
│  ├─ 汇总所有 FAIL/WARN 问题                                │
│  ├─ 按问题分类统计                                         │
│  └─ 输出结构化报告（MD 格式）                              │
│                                                             │
│  Step 3: 沉淀至乐享知识库                                  │
│  ├─ 上传报告到指定知识库                                   │
│  └─ 创建问题追踪表                                         │
│                                                             │
│  Step 4: 通知主理人                                        │
│  ├─ 摘要推送（仅 FAIL 级问题）                             │
│  └─ 完整报告链接                                          │
└─────────────────────────────────────────────────────────────┘
```

## 三、问题分类标准

### 3.1 严重度分级

| 级别 | 定义 | 处理要求 |
|------|------|----------|
| **P0 致命** | 站点死亡/SEO 归零/内容虚假 | 立即修复，当日闭环 |
| **P1 严重** | 品牌调性破坏/用户体验差 | 48 小时内修复 |
| **P2 一般** | 技术瑕疵/一致性差 | 本周内修复 |
| **P3 轻微** | 优化建议/品味提升 | 按需修复 |

### 3.2 问题类型分类

#### A. 技术类（Technical）
- T-001: 内链断裂
- T-002: 404 页面
- T-003: 资源加载失败
- T-004: JS 语法错误
- T-005: JSON-LD 结构化数据错误

#### B. 内容类（Content）
- C-001: 事实错误/信源缺失
- C-002: 标题误导/夸大
- C-003: 开篇无 hook
- C-004: 图注缺失/脱节
- C-005: 延伸阅读截断

#### C. 调性类（Tone）
- N-001: 含违禁调性词
- N-002: 标题过长/过短
- N-003: 标题含品牌后缀
- N-004: title ≠ h1
- N-005: h2/h3 自标数据
- N-006: 以问号结尾（恐慌腔）

#### D. SEO 类（SEO）
- S-001: 标题过短无搜索意图
- S-002: 描述缺失/过短
- S-003: 关键词堆砌
- S-004: 内链密度异常

#### E. 稳定性类（Stability）
- M-001: 空白页
- M-002: 内容乱码
- M-003: 样式断裂
- M-004: 导航错乱

## 六、团队协作规范

### 6.1 创作者自查清单（发布前）
- [ ] **h1 / og:title / twitter:title 不含品牌后缀（R-16）**；`<title>` 允许带 ` | AIHR数智引擎`
- [ ] **h1 == og:title == twitter:title**；`<title>` 等于 h1 或 h1 + ` | AIHR数智引擎`（R-17）
- [ ] 每个 figure 有 figcaption（T3）
- [ ] 开篇有 geo-answer-capsule 或 subtitle ≥30 字（T2）
- [ ] h2/h3 不自标数据出处（R-15）
- [ ] 延伸阅读链接文字完整（Gate 10）

### 6.2 QC Inspector 响应时效
| 问题级别 | 响应时效 | 通知方式 |
|----------|----------|----------|
| P0 致命 | 30 分钟内 | 即时 + 邮件 |
| P1 严重 | 2 小时内 | 即时 |
| P2 一般 | 当日 | 日报 |
| P3 轻微 | 本周 | 周报 |

### 6.3 整改闭环流程
```
QC Inspector 发现问题 → 生成报告 → 主理人审批 → 
分配责任人 → 创作者修复 → QC 复核 → 关闭问题
```


### 7.2 报告输出路径
