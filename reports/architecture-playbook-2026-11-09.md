# AIHR 站点架构打法与实施策略（设计 / 内容 / 技术三层）

> 2026-11-09｜性质：架构级打法，不是评估报告
> 触发：主理人批评「核心都是打补丁式缝缝补补，没有从设计架构、内容架构、技术架构的本质出发；内容排版不稳定、设计丑、颜色高级感不够；向外学优秀网站却没有一套系统打法和实施策略」
> **本件不是第 8 份规格文档**：它自带机器可读契约、内容 schema、单一页面骨架、可跑生成器与等价核验，实跑结果见 §九。文档若不能被代码消费，视为无效。

## 〇、结论先行

**根因不是「设计得不好」或「方案不够多」，是产物可直接手改 ⇒ 补丁永远比架构便宜。**

改一个 HTML 页面 5 分钟，改一层架构 5 天。只要产物页可写，每次局部问题的最优解都是补丁；补丁积累又抬高迁移成本，形成正反馈锁死。所以「从架构本质出发」不是态度问题，是**必须让补丁在物理上无处可打**：内容进数据、样式进唯一契约、chrome 进骨架、派生全部由生成器出。

三个反直觉的现测事实：

1. **仓库里已有 7 份架构/设计规格**，8/17 蓝图甚至写好了 P0→P3，并注明「任何阶段不得评估/暂不迁/局部修补降级」。实际只跑到 P0（样式外置）；10/17 锁定版直接写明「Astro/MDX 部分从未落地」，把不重构**冻结为事实标准**。缺的从来不是方案，是让方案不能被跳过的机制。
2. **站点其实有设计零件**：12 级 `--ink-0..950`、10 级 `--brand-50..900`、13 档字阶、115 个自定义属性。「颜色高级感不够」不是缺 token，是**有零件没装配规则**。
3. **排版不稳定的机制根因可定位**：`style.css` 102KB / 698 行里有 **85 个重复选择器**，`.article-header h1` 定义 5 次、`html` 4 次。真相源是「文件末尾后定义胜出」。这不是审美问题，是**样式判决机制不存在**。

## 二、第一性原理：三层批评其实指向同一个机制

用户提的三件事与上一轮的内容质量质疑，可以收束成一条因果链：

```
产物 = 可直接手改的 HTML
  → 局部问题总是用补丁最便宜                     （打补丁式缝缝补补）
  → 样式逐页覆写 + 85 个重复定义                 （排版不稳定）
  → 颜色靠事后归纳硬码成 token，无引用规则       （设计丑 / 高级感不够）
  → 内容结构靠人自觉，判断密度无法被结构保证     （本质是内容质量不够）
  → 架构迁移成本越来越高，被「事实标准冻结」      （7 份规格停摆）
```

因此解药不是「再设计一版配色」或「再写一份规范」，而是**换真相源**。这也解释了为什么 10/17 锁定版是危险的一步：它把补丁现状合法化，让每轮开工重新讨论「要不要重构」——该文档自己就把这称为「本项目最大的隐性成本」。

## 三、三层目标态与各自的单一真相源

| 层 | 当前 | 目标态 | 唯一真相源 |
|---|---|---|---|
| **设计架构** | 111 个颜色 token 混在同一命名空间；85 个重复选择器；深色靠 282 处 `[style*=...] !important` 精确接管 | L0 色阶 / L1 语义 / L2 组件，**单向自下而上**；单一 `ArticleLayout`；深色由同一色阶派生 | `ci/design-contract.json` + `templates/article-shell.html` |
| **内容架构** | 无；判断密度靠写作者自觉 | 每篇 = MD + frontmatter，把 `spine`（一句可复述判断）、`counterpoint`（对撞项）、`sources`、`related` 变成**必填结构字段** | `content/articles/*.md` + `ci/cluster-map.json`（复用，不重建） |
| **技术架构** | 435 个手写 HTML；39 个 build/gen/apply；派生靠人肉 | 生成器出 HTML / OG / JSON-LD / related / sitemap / chrome；产物禁手改 | `scripts/architecture/render_article.py` + `verify_parity.py` |

**选型判断（自行拍板，不逐项征询）**：不引入 Astro / Node 构建链。理由是 10/17 锁定版已把「无构建链」升为事实标准、GitHub Pages 部署约束、以及 8/17 蓝图自己列出的「轻量备选：自写 Python 生成器，复用现有 style.min.css + quality_gate」。改的是**真相源**，不是构建工具；换工具会把这次又变成一次大迁移，落回补丁逻辑。

**关键收敛**：上一轮把「内容质量」拆成 L1 可发现性 / L2 消费质量 / L3 判断密度，并指出 L3 任何站内数据都判不了。本轮把它变成 schema 必填项——判断密度不再依赖人的自觉，而由结构强制。**三轮批评收束到同一个动作。**

| **Stratechery** | **HTTP 403，未取到 CSS** | — | 不编造参数，本轮不作为参照 |

### 「高级感不够」怎么落到本站

外部站的高级感有相当部分来自**图库、定制字体、编辑部图片资源**。本站 B14 红线禁外链字体与字体文件、无图库、GitHub Pages 无 ICP，因此**不能靠换配色追高级感**。可迁移的只有四件事，已写进 `ci/design-contract.json`：

1. **中性色面积 ≥80%**，品牌色只用于链接、CTA、信号线、状态标记，禁大面积底色与渐变。
2. **三层引用方向单向**：L1 语义只能引用 L0 色阶，L2 组件只能引用 L1；禁止新增同义别名（`--insight-bg` 与 `--callout-bg` 属已登记债）。
3. **间距体系化**：当前实测无 spacing token，S1 建 ≥6 档；留白节奏由 scale 决定，不逐页调。
4. **断点极简**：`[520, 768, 1024]`，取 Butterick 而非 Smashing 的 20 个。

> 判别口诀（沿用项目铁律）：这次学的是「外部 professional 的秩序」还是「我们过去的样子」？前者才有效。范本卡缺「不可迁移」一栏＝盲目模仿。

## 五、系统打法：决策序，不是任务清单

清单会被拆开执行然后各自降级；决策序有硬依赖，跳步即失效。

```
D1 定关系 ──→ D2 定唯一真相源 ──→ D3 定不可写边界 ──→ D5 定迁移顺序 ──→ D6 定验收 ──→ D7 定退役
                    │
                    └─ D4 定内容 schema（可与 D1 并行，但不得先于 D2 写产物）
```

| 决策 | 内容 | 依赖 | 判断标准 |
|---|---|---|---|
| D1 | 三层 token 引用方向、正文列宽、断点、强调色使用规则 | — | 关系先于数值 |
| D2 | 哪些文件允许写：契约 / MD / shell / 生成器 | D1 | 一义一名，无同义真相源 |
| D3 | 产物页禁手改、禁页内 `<style>`、禁裸 hex | D2 | **补丁无处可打** |
| D4 | frontmatter schema 承载判断密度 | D2 | 缺 `spine`/`counterpoint` 即不可发布 |
| D5 | 先新文后存量、先高流量后长尾、按簇分批 | D3 | 每批可独立发布与回滚 |
| D6 | 结构等价 + 消费质量（读完/停留/二跳/跳出），不以 CTR 为增长目标 | D5 | 两轮结论合并 |
| D7 | 一次性脚本归档、历史规格标 superseded | D6 | 维护即 retire |

| 阶段 | 产出 | 验收 | **停止条件** | 回退边界 |
|---|---|---|---|---|

## 七、防停摆机制（本件最核心的一节）

**机制不是「再加一条门禁」**，而是 D3：让补丁不可写。但过渡期需要一个会失败的断言，否则第 9 份方案仍会被跳过。

- **S1 第一动作**：在 `publish.py` 接 `STEP 2.9 架构推进核验`——批次若包含**新增手写文章 HTML 且无对应 MD**，BLOCK；连续 3 批零迁移由 WARN 升为 BLOCK。必须带 `--self-test` 注入缺陷验证能拦（E-029 / E-030 / E-033 教训：装饰性门禁不如没有）。
- **本轮不接这条门**：S0 骨架尚未发布，此刻接入会把当前所有发布拦死造成停工。文档如实标注为 **S1 待办，不得宣称已防停摆**。
- **谁复核、多久**：主理人每周一 09:30 周复盘核对迁移配额与契约是否被代码消费；登记逃逸账本 E-034。
- **有效性判据**：`ci/design-contract.json` 已被 `render_article.py` / `verify_parity.py` 消费；schema 必填项被生成器断言；骨架实跑 25/25。**文档若只剩人读，视为第 8 份规格，判定本轮失败。**

## 八、停止做什么

1. 停止新增页内 `<style>` 与产物页 `style=` 里的裸 hex。
2. 停止新建语义别名 token 来「修一下观感」；新颜色必须先入 L0 色阶。
3. 停止一次性日期戳脚本（当前 35 个已是债，不再增加）。
4. 停止再写第 9 份架构规格文档；要写就写可被代码消费的契约。
5. 停止把「事实标准冻结」当架构决策，也停止每轮重新讨论「要不要重构」。
6. 停止把版式 / 颜色治理计入增长 KPI（沿用 11/09 读数报告结论）。
7. 停止用 CTR 当内容改造的验收指标。

实跑输出：

```
OK  bigtech-ai-restructure-three-tier-2026.md -> outputs/architecture-preview/... (5822 bytes)
self-test: 4/4 注入缺陷均被命中（工具有效）
核验：25 项，0 项异常   exit=0
```

过程中两次真实失败已修，未按「让核验通过」放宽断言：
- `{{TITLE}}` 在 title/og/twitter 出现 3 次 → 断言由「必须 1 次」改为「按预期次数」，仍拦截模板漂移。
- `description` 与 `lead` 被混成一个字段 → 拆为两个独立字段，`description` 取原页真实值。
- 核验器自身两处缺陷：C5 把 `class="counterpoint"` 误写成 `.counterpoint`；自检第 3 条写成恒真式。后者尤其关键——刚批评完装饰性门禁，不能自己再造一个。

**归因边界**：本件是架构打法与 S0 骨架，未改动任何线上页面、未发布、未接 `publish.py`。S1 涉及全站样式收敛，风险最高，建议以「基线只降不升」方式推进，不整版替换。
