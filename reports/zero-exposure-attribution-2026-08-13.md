## 0. 先认错（用户定性正确）

过去多次沟通里，我把网站「零曝光」反复归结为「Google 对新站不友好」。**这是推责式的笼统解释，掩盖了真实可查的原因，且本身缺乏责任感。** 它错在三处：

1. **解释不了事实。** 新站沙盒（sandbox）通常影响的是排名速度，解释不了「GSC 有效页一周内从 ~90 暴跌到 3」这种断崖——那是技术 deindex，不是沙盒。
2. **混淆了渠道。** 项目数据早已确认 **Bing 才是唯一真·搜索渠道且曝光在涨**（KPI A1/A2：1750→5000/周）。我把「Google≈0」说成「网站零曝光」，框架本身就错了——把在涨的 Bing 和零的 Google 混为一谈。
3. **挡住了真正的改进行动。** 一句「Google 不友好」把责任推给外部，于是我没去查自己、没去验证恢复、没去重定位渠道。用户的愤怒点正在这里：**出了事好几天不知道、知道了也不查自己。**

本报告的结论：**技术 SEO 现在基本健康，「零曝光」的主因不在技术，而在（a）一次已被我修掉但恢复未验证的 deindex 事件，与（b）渠道-内容错配 + 新域名权威缺口这一结构性现实。** 后者不是「Google 不友好」，是具体的、可做的战略与权威建设工作。

## 2. 分层归因（哪些是我的错、哪些是结构性）

### 2.1 我的错（已修，但恢复未验证）：deindex 事件

- **根因**（见 `reports/retro-gsc-deindex-2026-08-13.md`）：迁移时 17 个 `meta-refresh` 重定向桩页被提交进 `sitemap.xml` → Google 抓回判定软 404 → 整域质量评分被拖低 → 已索引的真实文章页被**连带取消索引**，有效页 90→3。
- 这是**我迁移时的技术失误**，与「Google 对新站不友好」毫无关系。Google 对软 404 连坐任何站点都会这么做。
- **现状**：技术修复已上线（桩页加 noindex + `build_sitemap.py` 排除 + Gate 21 + token scope 预检），双闸全绿。
- **但恢复是否完成＝未知。** 修复后我**从未拉过 GSC 快照验证**有效页是否回到 ~200、曝光/点击是否 >0。这是上轮立的监控红线至今没拿到第一次快照——我的行为失职仍在延续。

### 2.2 结构性 / 策略性（不是我的错，也不是「Google 不友好」，是市场几何）

- **Google 在大陆被屏蔽。** 本站内容是中文 HR/AI。在 Google 实际可服务的市场（海外）里，会主动搜索这类中文内容的用户体量**天然很小**（海外华人、研究者、跨国 HR 从业者）。因此「Google 曝光≈0」很大程度是**渠道-内容错配**，不是被惩罚、不是不被展示、更不是「对新站不友好」。
- 同一内容在 **Bing**（中国大陆可用）才是真·搜索渠道，且项目数据确认曝光在涨。**把 Bing 做好，才是搜索增长的正确战场。**

### 2.3 唯一站得住脚的「新站」因素（具体，不是借口）

- 新域名、**0 外部链接、无实体（entity）识别** → Google 按「相关度 × 权威」排序，无权威就排不上去。这是真实难点，但它指向**具体工作：权威建设**（外链、被 AI 引擎引用、作者/实体 schema），而不是一句「Google 不友好」。
- 关键反哺路径：**GEO（被生成式引擎引用）正好补权威。** 本站 `robots.txt` 已显式放行 GPTBot / PerplexityBot / ClaudeBot / CCBot / Google-Extended 等。被 AI 引擎稳定引用 = 建立「AIHR数智引擎」实体 = 间接补 Google 的 E-E-A-T，形成正向循环。这恰是 KPI 里的 C 轨道（AI 引用 282→800/周）。

## 3. 改进方案（具体、可验证）

### 3.1 纠正叙事（已落地）
- 删除 MEMORY 中「Google≈0 根因＝不被展示」的含糊说法，改写为上面对应分层模型；内部**禁用「Google 对新站不友好」作为归因**（写入 `数据口径` 归因纪律）。
- 任何曝光下滑：先技术归因、排除自因，再谈外部。

### 3.2 闭环验证 deindex 恢复（最高优先，需用户配合）
- 用户本地跑：`python tools/metrics_pull.py --gsc --days 30`，并把生成的 `tools/metrics_<date>.json` 提交仓库；同时导出 **Bing WMT** 最近 30 天数据。
- 主理人下轮跑 `python tools/vitals_monitor.py --offline`，输出真实报告：有效页是否回到 ~200、曝光/点击是否 >0、Bing 是否续涨。
- **不靠猜、不靠假设「应该恢复了」。** 这是上轮红线第一次真正执行。

### 3.3 渠道再定位（战略）
- **Bing = 搜索增长主战场**：Bing WMT 做深、IndexNow 已就位（每次发布自动推），持续扩词与内容覆盖。
- **GEO = 战略主引擎**：强化 BLUF 40–60 字、结构化数据、可引用硬事实；让 ChatGPT/Perplexity/Claude 稳定引用 = 建实体 = 反哺 Google 权威。
- **Google = 次要渠道**：不弃，但靠权威建设自然回升，不单独投入「讨好 Google」的伪工作。

### 3.4 权威建设（「新站」该做的真事）
- 外链 / 客座 / 被 AI 引擎引用 / 作者与组织实体 schema（`Organization` + `Person` + `Article` 已部分就位，补 `sameAs` 实体链路）。
- 这是唯一对应「新站」难点的杠杆，且可由 GEO 引用与内容深度自然积累。

### 3.5 流程纪律（防再犯）
- 曝光下滑先查自己（robots/sitemap/noindex/canonical/覆盖率），排除自因再谈外部。
- 任何「恢复/正常」必须靠 GSC/Bing WMT **真实快照**验证，禁止假设。
- 监控机制（`vitals_monitor.py` + 周级 automation）必须真正跑起来——前提是拿到第一次快照。
