# CM-2026 产品形态规格：从「索引」升级为「标准驱动的推荐罗盘」

> 版本：v1 · 2026-09-21 · 状态：**已采纳（D-030 / D-031 / D-032 / D-033）** · 真源：`projects/ai-hr-capability-model/09-PRODUCT-FORM.md`
> 镜像：乐享「AIHR项目知识库」/ CM-2026 目录（source_commit 见仓库 main 最新 CM-2026 commit）
> 用途：定义「策展 / 桥梁」从资产目录升级为产品的具体形态，作为 P3 工程实现的契约。

## 一、诊断：为什么现在是「index 不是 product」

| 症状 | 实测 | 根因 |
|---|---|---|
| 策展页是资产目录 + 叙事 | `bridge/index.html` 实测 0 个表单、0 input、0 textarea、0 select（D-001，2026-09-19） | 页面在「列资产」，没有入口触发器 |
| 读者不知道「我来干嘛、来完干嘛」 | 全站跳出率 96.59%（D-002 结构成因之一） | 三支柱互不连接，页面不生产路径 |
| 能力标准已立，但没驱动表层 | 标准在仓库、页面在列清单 | 标准与表层脱节，标准只是被引用而非被运行 |

**结论**：问题不是「资产不够」，是「缺一层把标准变成路径的推荐逻辑」。这不是重建，是**在标准之上补一层推荐引擎**。

## 二、核心原则：推荐 ≠ 筛选匹配（D-031）

| 维度 | 筛选匹配（否决） | 推荐（采纳） |
|---|---|---|
| 结构 | 双边：用户填需求 + 系统从已建库返回匹配项 | 单边：标准侧已写好「X 型在 Y 阶段该做什么」，用户来取 |
| 数据依赖 | 需企业侧数据集（JD / 需求库） | 无需建库——标准即数据源 |
| 生成方式 | 实时查询 / 在线 AI 回答 | 离线生成、静态落盘 |
| 可索引性 | 实时内容搜索引擎抓不到，零 GEO（D-015） | 静态页可被抓取、被引用，直打 GEO 集中度 KPI |
| 法律 | 撮合/简历处理需人力资源服务许可（D-006）；爬 JD 建库有判例风险（D-007） | 不撮合、不抓 JD、不处理简历 |

**一句话**：匹配的「库」永远空（法律 + 冷启动），所以匹配是伪命题；推荐是标准的外显，把我们已经 authored 的核心资产变成产品。

## 三、升级后的产品形态：标准驱动的推荐罗盘

三层结构，均静态、离线、可索引：

### 1. 入口（触发器）—— 不是「选岗位」，是「你是谁 + 你在哪」
- 角色分 A / B / C 型（已在能力模型 v1 第二节定义）：A 型用 AI 提效（仅门槛）、B 型为组织设计 AI 转型方案（主体）、C 型治理人机混合劳动力（主体）。
- 转型阶段分：试点 / 规模化 / 重构。
- 交互：单选 + 轻交互，**不提交任何简历或 JD**。

### 2. 引擎（标准驱动）—— 能力模型即推荐大脑
- 给定 `(角色, 阶段)`，模型 prescribe 一条路径：该读哪几篇（从 294 篇里按能力项挂接）、该做哪个自评、该补哪块能力。
- 这是**编辑逻辑编码进标准**，不是实时检索。路径由人工基于标准设计、静态固化。

### 3. 出口（闭环）—— 用户拿到「一条路径」而非「一张列表」
- 路径末端指向已有三支柱资产（静态页、测评、文章）。
- 用户离线自评 → 生成静态画像页 → 对照标准 → 推荐下一步。
- 企业侧「组织情境 + 能力要求」输入（D-009）的语义澄清：**是调推荐精度的情境输入，不是发匹配请求**——不进入双边匹配，不建库。

## 四、P3 模块重定义（对应 04-PLAN.md）

| 原命名 | 重定义后 | 形态约束 |
|---|---|---|
| A 模块「岗位能力画像」 | **能力自评罗盘**：离线、证据驱动、输出在标准上的位置 | 静态落盘、进 sitemap；V-05 硬排除性格分数 |
| B 模块「能力自评 → 岗位对照」 | **标准驱动的推荐路径**：输入角色×阶段 → 输出路径 | 不接测评分数、不做岗位匹配 |
| 策展 / 桥梁页 | **推荐罗盘入口 + 静态路径汇总** | 含角色×阶段入口；产出非 asset index 的推荐路径；无非 index 跳转 |

## 五、验收信号（与项目纪律一致：不接受「完成了」）

| 信号 | 怎么验 |
|---|---|
| bridge 页不再是 index | 含「角色×阶段」入口；路径区为非 asset index 的推荐路径（非简单链接列表） |
| 推荐是静态非实时 | 推荐页为 `.html` 落盘且进 sitemap；无在线 AI 回答组件 |
| 不越红线 | 全站无简历上传 / 职位匹配 UI（V-01 扩展 + 人工核）；无招聘平台爬虫（V-03） |
| GEO 增益 | 发布后集中度从 85.8% 下降、跳出率从 96.59% 下降（分段取数） |

## 六、不在本次范围内（明确划界，防范围蔓延）

- 不做职位推荐 / 简历处理 / 招聘平台对接（D-006）。
- 不做实时 AI 对话式推荐（D-015）。
- 不做性格测评 → 岗位匹配（X-002）。
- 不把企业情境输入做成双边匹配市场（D-031 语义边界）。

## 七、商业化价值：权威转化，而非数据/匹配变现（D-033）

> 本节回答「这个不碰数据、不做匹配的推荐罗盘，靠什么变现」。结论先行：**价值在权威转化，不在数据囤积。**

### 7.1 被红线挡死的变现路径（不是我们不做，是做了就违法或零价值）

| 路径 | 为什么不能走 |
|---|---|
| 简历/职位匹配撮合 | 需人力资源服务许可（D-006）；个人主体 + 订阅号无资质 |
| 抓取 JD 建库后再变现 | 2026-06 北京互联网法院《反不正当竞争法》数据专款首例，判赔 23 万余元（D-007） |
| 卖用户测评/简历数据 | 非法且违背「正念正见」品牌；D-032 已钉死不回传、不收集 |
| 实时 AI 对话式付费问答 | 在线内容搜索引擎抓不到，零 GEO；且与 D-015 冲突 |

### 7.2 真正可行的变现架构（按是否需要资质分层）

| 层级 | 形态 | 是否需要资质 | Andy 能否做 |
|---|---|---|---|
| **L0 权威资产** | 能力标准被引用（GEO）、免费罗盘 + 测评作引流与参与 | 否 | ✅ 已建 |
| **L1 知识产品** | 付费深度报告 / 白皮书 / 能力模型框架授权 | 否 | ✅ 可作 |
| **L2 专业服务** | 企业培训（AI 转型 HR 能力）、OD 顾问 / 组织设计咨询、演讲邀约 | 否（个人专家身份可交付，非中介） | ✅ 可作 |
| **L3 平台/撮合** | 招聘、简历处理、人才匹配市场 | **是（需许可）** | ❌ 红线挡死（D-006） |

### 7.3 漏斗逻辑（产品是漏斗顶端，不是市场本身）

```
标准(免费,GEO权威) → 罗盘(参与,降跳出) → 测评(用户自识能力缺口) → 专家服务(付费)
```

- 产品本身保持**免费、非商业化**；变现的是产品背后的人（OD 专家），不是平台抽成。
- 罗盘与测评的任务是把匿名流量变成**有质量的专家服务线索**，而非变成可交易的用户数据。
- 测评结果留在用户浏览器端（D-032）——这恰恰是合规卖点：我们证明价值靠标准厚度，不靠窥探用户。

### 7.4 该追的北极星（vs 虚荣指标）

| 追 | 不追 |
|---|---|
| GEO 集中度下降（被更多页引用） | 用户数据量与日活 |
| 跳出率下降（罗盘生效） | 匹配交易笔数（我们不做） |
| 私域咨询询盘率 / 付费服务转化 | 简历库规模 |
| 付费报告 / 培训 / 咨询的复购与转介 | 广告点击 |

### 7.5 结论

这个产品的商业价值**不建立在「拿用户数据」之上，而建立在「把标准做厚、让资产可被推荐、让专家可被找到」之上**。越想拿简历和测评结果，越会撞上 D-006/D-007 的墙——那堵墙正是当初从匹配改做推荐的根本原因。产品的终局是**一个被行业引用的权威标准 + 一条专家服务转化漏斗**，不是一个人力资源市场。
